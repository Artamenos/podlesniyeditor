# Публикация на Timeweb

Сайт экспортируется в статические файлы. На хостинг загружается **содержимое `out/`**, включая `_next`, `en`, `media`, `fonts` и `404.html`. Запуск Next.js, Node.js и база данных на хостинге не нужны.

Текущая площадка: виртуальный хостинг Timeweb, сайт **Podlesniy**, технический домен **http://cp29116.tw1.ru**. SSH: `cp29116@vh430.timeweb.ru:22`. Папка сайта: `/home/c/cp29116/Podlesniy/public_html`.

## Что уже настроено

`Site checks and Timeweb deploy` запускает установку по lock-файлу, TypeScript, ESLint, production-сборку и проверки RU/EN при push в `main` и pull request. Готовую сборку можно скачать в разделе **Artifacts → site-static** завершённого запуска.

Загрузка на хостинг запускается вручную: **Actions → Site checks and Timeweb deploy → Run workflow → main → deploy**. Обычный push проверяет и собирает сайт. Сначала настройте доступ и проверьте папку назначения.

## Данные Timeweb

Для готового способа загрузки нужен SSH-доступ с `rsync`. На виртуальном хостинге Timeweb включите SSH и создайте отдельный сайт. Узнайте:

- SSH-сервер (не домен сайта), логин и порт;
- абсолютный путь к папке сайта, обычно вида `/home/буква/логин/имя-сайта/public_html`;
- домен, привязанный к этой папке, или технический домен для первой проверки.

Для Timeweb Cloud/VPS сначала нужен настроенный веб-сервер со статическим корнем сайта. Путь должен указывать на отдельную папку сайта, а не на корень аккаунта. Перед первой загрузкой сохраните копию существующих файлов этой папки.

## GitHub Actions

В репозитории откройте **Settings → Environments → New environment**, имя `timeweb`. В **Deployment branches and tags** разрешите только `main`.

Добавьте **Environment variables**:

| Имя | Значение |
|---|---|
| `TIMEWEB_HOST` | SSH-сервер из панели Timeweb |
| `TIMEWEB_USER` | Логин SSH |
| `TIMEWEB_PORT` | `22`, если в панели не указан другой порт |
| `TIMEWEB_PATH` | Полный путь к папке сайта без `~` |

Добавьте **Environment secrets**:

| Имя | Значение |
|---|---|
| `TIMEWEB_SSH_KEY` | Приватный SSH-ключ для загрузки из Actions |
| `TIMEWEB_KNOWN_HOSTS` | Строка ключа SSH-сервера в формате `known_hosts` |

Для проекта создан отдельный SSH-ключ; его приватная часть сохранена в `TIMEWEB_SSH_KEY`. Публичную часть нужно разрешить в `~/.ssh/authorized_keys` пользователя `cp29116`. При замене ключа создайте отдельную пару для этого проекта. Публичную часть добавьте на Timeweb по его инструкции, приватную — только в GitHub Secret. Пароли и приватные ключи не кладите в репозиторий и не присылайте в чат. Отпечаток SSH-сервера проверьте через панель или поддержку Timeweb перед сохранением `TIMEWEB_KNOWN_HOSTS`; workflow не отключает эту проверку.

## Первая публикация

1. Убедитесь, что выбран правильный домен и папка сайта. Настройте SSL в панели Timeweb.
2. Запустите workflow вручную с `deploy` из ветки `main`.
3. Проверьте `/`, `/en/`, меню языка, видео, контакты и загрузку локальных изображений/шрифтов.
4. В сборку включён `.htaccess`: главная страница — `index.html`, страница ошибки — `/404.html`. Загрузка заменяет этот файл в выбранной папке сайта.

Папка на хостинге должна существовать и быть доступна SSH-пользователю для записи. Workflow сначала загружает ресурсы, затем HTML. Лишние старые файлы автоматически не удаляются; их можно очистить отдельно после проверки публикации. На удалённых файлах не храните единственный экземпляр материалов.

После выбора рабочего домена добавим точные canonical/hreflang URL и sitemap. До этого домен в SEO-настройках не выдумывается.
